# GigaChat ML: настройка и рабочий профиль

`backend/presentation_ml` реализует внешний интерфейс из `ML_CONTRACT.md`.
Генерация и правка делают не более одного запроса к модели на операцию.
Явная неподдерживаемая структурная команда может быть отклонена без запроса.
Автоматических платных повторов, LLM-судьи и подмены ошибочного ответа fixture нет.

## Текущий выбор

| Уровень | Значение | Что означает |
|---|---|---|
| Модель | `GigaChat-3-Ultra` | Текущая модель пользователя; другие модели/провайдеры отложены |
| HTTP API | `https://api.giga.chat/v1` | Версия API провайдера |
| Промпт | `PM_ML_PROMPT_VERSION=v4` | Рабочий профиль содержания, теперь по умолчанию |
| Внутренний формат правки | `revision-wire-v3` | Формат ответа модели; внешний ML-контракт не менялся |

Эти номера версий независимы. Основание выбора и ограничения —
[синтетическая оценка](ML_EVALUATION_2026_11_01.md). Выбор v4 не означает
доказанную точность на любых докладах или готовность production.

## Ключ и сертификат

В игнорируемом `backend/.env` задаются:

```dotenv
GIGACHAT_CREDENTIALS=<Authorization key проекта>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-3-Ultra
PM_ML_PROMPT_VERSION=v4
```

Нужен Authorization key, не Client ID и не временный access token. Официальный
SDK получает и обновляет токен самостоятельно; менять ключ каждые 30 минут
не требуется. Ключ передаётся только worker, не frontend и не API readiness.
Не выводите `.env`, токены, доклады и команды в журналы.

`compose.gigachat.yaml` подключает env_file к worker, включает модуль на api/worker
и монтирует публичный `backend/certs/gigachat-root.crt` только для чтения.
Проверка TLS включена. Сертификат получен по ссылке официальной документации;
его нужно обновить при изменении цепочки доверия. Никогда не помещайте секреты
в сертификат и не отключайте проверку TLS для обхода сетевого сбоя.

## Запуск

Обычный `compose.yaml` намеренно использует fixture. Реальная модель включается
явным override:

```bash
docker compose -f compose.yaml -f compose.gigachat.yaml build api
docker compose -f compose.yaml -f compose.gigachat.yaml up --no-build -d --wait
docker compose -f compose.yaml -f compose.gigachat.yaml exec web nginx -s reload
```

Сайт: `http://localhost:8080`. Готовность: `/api/v1/health/ready` →
`{"status":"ok","ml_adapter":"module"}`. Readiness проверяет импорт и интерфейс,
а не авторизацию или качество модели. Импорт не загружает SDK и не делает inference.

После пересоздания api в этом стенде наблюдался 502 через nginx при здоровом API;
`nginx -s reload` восстановил доступ. Проверяйте readiness через публичный порт
после обновления контейнеров. Не принимайте прямую проверку контейнера за проверку
всего пути через web.

Общий backend-образ достаточно собрать один раз через `build api`.
Для обновления только ML можно пересоздать api/worker с `--no-deps --no-build`,
затем перезагрузить nginx. Одновременная сборка нескольких сервисов с тем же
тегом образа ранее вызывала конфликт экспорта образа.

Если меняется только ключ или профиль окружения, пересоздайте worker:

```bash
docker compose -f compose.yaml -f compose.gigachat.yaml up --no-build --no-deps -d --force-recreate worker
```

В личном проекте оставляйте один одновременный запрос. Не запускайте CLI-проверку
параллельно с заданиями сайта на том же аккаунте. Несколько независимых стендов
потребуют общего ограничителя. Настоящий production остаётся отдельной задачей.

## Генерация и нормализация

Модель возвращает кандидат документа. Модуль валидирует результат и при отсутствии
краевых макетов добавляет title/closing с уже полученным `document.title`.
Заключение не содержит жёстко заданной русской фразы, поэтому английский исходник
не получает русское заключение от нормализатора.

Внутренний заголовочный title/section перед содержательным слайдом без заголовка
может быть объединён с ним в text. Заголовок, подпись, подзаголовок, подписи
колонок, все строки и заметки сохраняются. Объединение выполняется только при
читаемом объёме; длинная пара остаётся без изменения. Для правки оно не применяется.

В профилях v3–v7 источник короче 1000 Python Unicode code points получает целевой
объём min(slideCount, 4). Это эвристика, не правило внешнего контракта. Если после
добавления краевых слайдов объём превышен, соседние короткие разделы упаковываются
дословно в один/два text-слайда: body не более 800 символов, заметки сохраняются,
итог снова проходит строгую проверку UTF-16 и размера. Если упаковка не помещается,
ответ отклоняется; текст не обрезается и новый платный запрос не запускается.
Часть заголовков при такой упаковке может повториться в body — известная
косметическая особенность в пользу сохранения строк.

## Выборочная и общая правка

Внутренний ответ: `{"status":"applied","document":...}` либо
`{"status":"unsupported","document":null}`. Эта оболочка не возвращается backend.

При явных целях модель получает полный контекст, но возвращает только выбранные
замены в document.slides. Схема ограничивает их число и допустимые ID. Код проверяет
точное множество ID, затем подставляет замены в замороженную исходную копию.
Публичный результат всегда полный, с исходным порядком и количеством. Невыбранные
слайды целиком и общий title сохраняются, даже если выбраны все номера.
Списки целей и исходный документ передаются провайдеру копиями; проверка результата
использует неизменяемый снимок целей. Мутация payload не расширяет разрешённую область.

Без явных целей модель возвращает все слайды; ID, порядок и количество проверяются,
а содержимое и общий title могут меняться. Входной объект не изменяется.

`capabilities.py` до запроса отклоняет распознанные явные RU/EN команды добавления,
удаления и перемещения слайдов. Проверены отрицания, цитаты и правки slide title/body.
Это консервативная проверка, а не универсальный интерпретатор произвольного языка.
Неизвестные формулировки ещё зависят от модели и проверки результата. Отказ →
NotImplementedError; невалидный кандидат → ValueError, без фиктивного успеха.

## Версии промптов и граница провайдера

`prompts.py` и `prompt_templates/` хранят версии. Старый v1 сохранён точно,
его сообщения проверяются хешами. v2 подробнее задаёт ограничения; v3 добавляет
короткий бюджет; v4 сохраняет адресатов, условия и степень уверенности.

v5–v7 оставлены как явно выбираемые исследовательские варианты, не рекомендуются
основными: v5 проверяет покрытие извлечённых заголовков, v6 — самостоятельный короткий
промпт, v7 — дословные source_quotes перед пересказом. В v7 буквальное наличие цитат
проверяется, внутреннее поле удаляется, фрагменты добавляются в notes. Это НЕ проверка
логического следования: реальная цитата может сопровождать неверный пересказ.
Содержательные слайды требуют цитату, title/closing допускают пустой список.
После последующих правок старые цитаты также требуют сверки. Провалы экспериментов
зафиксированы в отчёте; увеличение номера не означает улучшение качества.

`transport.request_document` вызывает JsonProvider. Единственный адаптер сейчас —
`providers/gigachat.py`, официальный SDK, ленивый клиент, TLS, `max_retries=0`.
Незнакомый `PM_ML_PROVIDER` даёт NotImplementedError. Другие провайдеры не получают
этот ключ и не включаются автоматически. Интерфейс подготовлен для расширения,
но смена провайдера не реализована и в текущую работу не входит.

## Экономная проверка

14 вымышленных случаев, включая девять разноплановых, перечислены в
[ML_SYNTHETIC_CASES.md](ML_SYNTHETIC_CASES.md). Ожидаемые факты и недопустимые выводы
хранятся отдельно от text и не передаются модели.

Из `backend`, без обращения к модели:

```bash
uv run --locked python -m tools.ml_acceptance --case finance-plan-vs-actual --output /private/review
```

Без сохранённого ответа будет `not_run`, а не успешная приёмка. Для осознанного
нового вызова добавляются `--live` и явный `--case`. `--save-candidates` сохраняет
сырой ответ до проверки, только если все выбранные случаи помечены synthetic=true.
Файлы содержат текст, храните их приватно. Кандидат можно повторно подставлять
в локальные проверки нормализатора без провайдера. В server logs он не попадает.

Перед вызовом пишется статус started. Неуспешная/прерванная попытка блокирует
неявный повтор в том же каталоге. Изменение профиля или входа также не маскируется
перезаписью результата. Новый каталог выбирается намеренно после диагностики.
Сохраняются модель, scope, версия/хеш промпта и политики нормализации. Ошибки
описываются классами/флагами, без текстов исключений и ключей.

Последняя проверка: 116 тестов прошли в шести ML/adapter/runner-файлах, Ruff прошёл.
Это целевой набор, не повтор полного backend/DB-интеграционного набора.
Сквозной браузерный путь v4 + wire-v3 прошёл за 17,56 с в одном синтетическом случае.
Девять выбранных документов экспортированы, 59 слайдов проверены по XML и рендерам
LibreOffice; одобрение пользователем ещё ожидается. Повторяемость качества,
нативный PowerPoint и реальные материалы требуют отдельной приёмки.

SDK обновляет токены, но интервальные ConnectError/SSLEOFError ранее встречались;
точная причина не установлена. Успешные последующие запросы не доказывают устранение
сетевой проблемы. До deadline оставляется запас 10 с; завершение локального процесса
не гарантирует отмену уже отправленного запроса у провайдера.
