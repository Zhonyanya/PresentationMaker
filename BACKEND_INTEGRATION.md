# Подключение бэкенда

Инструкция для разработчиков, которые подключают языковую модель. Фронтенд уже готов: от бэкенда нужен **один эндпоинт**, который возвращает JSON по контракту ниже. Переписывать компоненты не придётся.

## 1. Что нужно сделать

1. Реализовать `POST /api/generate` (раздел 2).
2. Внутри — вызвать языковую модель и получить от неё JSON строго по схеме (раздел 4).
3. Проверить ответ на сервере той же схемой и вернуть клиенту.
4. Переключить фронтенд в режим `http` (раздел 6) и пройти чек-лист (раздел 8).

Ключ API модели хранится **только на сервере**. Всё, что лежит во фронтенде (включая переменные `VITE_*`), видит любой пользователь.

## 2. Эндпоинт

```
POST {VITE_API_BASE_URL}/api/generate
Content-Type: application/json
Accept: application/json
```

### Запрос

```json
{
  "text": "Полный текст доклада или план выступления…",
  "title": "Итоги учебного года",
  "slideCount": 8
}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `text` | string | да | Исходный текст, 100–60 000 символов. Уже без пробелов по краям. |
| `title` | string | нет | Название, до 200 символов. Если нет — придумайте по тексту. |
| `slideCount` | integer | да | Желаемое число слайдов **с титульным и заключительным**, 3–20. Примерное. |

Фронтенд проверяет запрос до отправки, но сервер обязан проверить его ещё раз.

### Ответ `200 OK`

```json
{
  "title": "Итоги учебного года",
  "slides": [
    { "id": "slide-1", "layout": "title", "title": "Итоги учебного года", "subtitle": "Доклад на коллегии", "caption": "Москва · 2026" },
    { "id": "slide-2", "layout": "section", "title": "Результаты года", "subtitle": "Что удалось сделать" },
    { "id": "slide-3", "layout": "text", "title": "Общие итоги", "body": "Первый абзац.\nВторой абзац.", "notes": "Что сказать устно" },
    { "id": "slide-4", "layout": "bullets", "title": "Ключевые достижения", "bullets": ["Первое", "Второе", "Третье"] },
    { "id": "slide-5", "layout": "two-column", "title": "Кадры", "leftTitle": "Проблемы", "left": ["…"], "rightTitle": "Решения", "right": ["…"] },
    { "id": "slide-6", "layout": "closing", "title": "Спасибо за внимание", "subtitle": "Контакты докладчика" }
  ]
}
```

#### Общие поля слайда

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | string | нет | Уникальный id. Если не передать или повторить — фронтенд сгенерирует сам. |
| `layout` | string | да | Один из макетов ниже. |
| `title` | string | да | Заголовок, до 200 символов. |
| `notes` | string | нет | Заметки докладчика, до 10 000 символов. Попадают в заметки PPTX. |

#### Макеты

| `layout` | Назначение | Поля |
|---|---|---|
| `title` | Титульный | `subtitle?` (до 400), `caption?` (до 200: город, дата, докладчик) |
| `text` | Заголовок и 1–2 абзаца | `body` (до 4000; абзацы через `\n`) |
| `bullets` | Маркированный список | `bullets: string[]` (до 12 пунктов, каждый до 1000; лучше 3–6 по 5–15 слов) |
| `two-column` | Сравнение / два направления | `leftTitle?`, `left: string[]`, `rightTitle?`, `right: string[]` |
| `section` | Разделитель между частями | `subtitle?` (номер раздела фронтенд ставит сам) |
| `closing` | Заключительный | `subtitle?` |

Ограничения на весь ответ: `title` до 200 символов, от 1 до 60 слайдов. Неизвестный `layout` или лишняя вложенность — ошибка контракта. Лишние поля игнорируются.

**Машиночитаемая схема:** `docs/generate-request.schema.json` и `docs/generate-response.schema.json` (JSON Schema 2020-12). Генерируются из исходных Zod-схем командой `npm run schema` — после изменения контракта перегенерируйте.

Источник правды — `src/domain/presentation.ts` (`generateRequestSchema`, `generateResponseSchema`).

## 3. Ошибки

Тело ошибки (желательно):

```json
{ "error": { "code": "TEXT_TOO_SHORT", "message": "Текст слишком короткий для презентации" } }
```

| HTTP | Что увидит пользователь | Повтор |
|---|---|---|
| 400, 422 | `error.message` с сервера — **пишите его для сотрудника, по-русски** | нет |
| 408, 504 | «Сервер не успел подготовить презентацию…» | да |
| 429 | «Слишком много запросов…» | да |
| 5xx и прочие | «На сервере произошла ошибка…» | да |
| ответ не по контракту | «Сервер вернул данные в неожиданном формате…» (подробности — в консоли браузера) | да |
| нет соединения | «Не удалось связаться с сервером…» | да |

Для 5xx текст сервера пользователю не показывается — туда можно писать технические детали. В окне ошибки есть раскрывающийся блок «Подробности для разработчиков» с кодом, статусом и телом ответа.

Логика — `src/api/http-api.ts`, тексты — `src/api/errors.ts`.

## 4. Как получить от модели правильный JSON

Рекомендации (под любую модель — Claude, GigaChat, YandexGPT и др.):

1. **Structured output / JSON-режим**, если модель поддерживает: передайте `docs/generate-response.schema.json` как схему ответа. Если нет — опишите схему в системном промпте и попросите вернуть только JSON.
2. **Всегда валидируйте ответ на сервере** (Pydantic / Zod / jsonschema). При ошибке — один повтор запроса к модели с текстом ошибки валидации, затем 502 с понятной ошибкой.
3. Пример системного промпта (адаптируйте):

```text
Ты готовишь презентацию для официального выступления сотрудника министерства образования.
По исходному тексту составь структуру слайдов и верни ТОЛЬКО JSON по схеме.

Правила:
- Первый слайд — layout "title", последний — "closing".
- Всего примерно {slideCount} слайдов, включая титульный и заключительный.
- Опирайся только на факты из исходного текста. Не добавляй цифры, имена и выводы, которых нет в тексте.
- Заголовки — до 8 слов, без точки в конце.
- В "bullets" — 3–6 пунктов по 5–15 слов, без точки в конце.
- "two-column" — для сравнений: было/стало, проблемы/решения, плюсы/минусы.
- "section" — только если в докладе есть крупные части; не больше одного на 3–4 слайда.
- "text" — когда мысль нельзя разбить на пункты; не больше 2 абзацев.
- В "notes" — что докладчик скажет устно на этом слайде, 2–4 предложения из исходного текста.
- Официально-деловой стиль, русский язык.
```

4. Длинные доклады: если текст не влезает в контекст модели, сначала сделайте план (шаг 1 — список разделов), затем генерируйте слайды по разделам.
5. Время: ТЗ требует ≤ 25 минут. Фронтенд ждёт `VITE_API_TIMEOUT_MS` (по умолчанию 25 минут) и даёт пользователю отменить ожидание. Отмена закрывает соединение — по возможности прекращайте генерацию на сервере при обрыве.

## 5. CORS и прокси

- **Один домен** (рекомендуется): отдавайте `dist/` и `/api` с одного хоста (nginx). `VITE_API_BASE_URL` оставьте пустым.
- **Разные домены**: разрешите CORS для `POST` и заголовка `Content-Type` с домена фронтенда; `OPTIONS` должен отвечать 204.
- **Разработка**: `VITE_DEV_PROXY_TARGET=http://localhost:8000` — `npm run dev` проксирует `/api/*` на бэкенд без CORS.

## 6. Переключение фронтенда

Создайте `.env` (или `.env.local`) рядом с `package.json`:

```bash
VITE_API_MODE=http
VITE_API_BASE_URL=
VITE_API_TIMEOUT_MS=1500000
VITE_DEV_PROXY_TARGET=http://localhost:8000
```

Перезапустите `npm run dev`. Бейдж «Демо-режим» исчезнет, экран генерации перестанет показывать имитацию этапов и будет показывать честное ожидание с таймером. Переменные `VITE_*` вшиваются при сборке — для production задайте их перед `npm run build`.

Выбор реализации — `src/api/index.ts`. Компоненты используют только интерфейс `PresentationApi` (`src/api/types.ts`).

## 7. Прогресс генерации (по желанию)

Сейчас HTTP-клиент не знает о ходе генерации, и интерфейс не обещает точный прогресс. Если захотите показывать этапы:

1. Отдавайте ответ как Server-Sent Events: события `stage` с `{ "stage": "analyze" | "structure" | "content" | "slides" | "design" }` и финальное `result` с JSON ответа.
2. В `src/api/http-api.ts` читайте поток и вызывайте `options.onStage(stage)`, затем валидируйте `result` как сейчас.
3. Поставьте `reportsStages: true` — экран генерации сам переключится на список этапов (без пометки «Демо»).

Компоненты менять не нужно.

## 8. Чек-лист приёмки

- [ ] `curl -X POST …/api/generate -H 'Content-Type: application/json' -d '{"text":"…","slideCount":8}'` возвращает JSON, который проходит `docs/generate-response.schema.json`.
- [ ] Первый слайд `title`, последний `closing`, число слайдов близко к `slideCount`.
- [ ] Короткий текст → 422 с понятным `error.message`.
- [ ] Ошибка модели → 5xx, на фронте видно «Повторить».
- [ ] Отмена на экране генерации не оставляет «висящих» запросов к модели (по возможности).
- [ ] 5+ реальных докладов: структура соответствует содержанию, факты не выдуманы, генерация ≤ 25 минут.
- [ ] Скачанный PPTX открывается в PowerPoint, текст редактируется.
- [ ] В коде фронтенда и в `dist/` нет ключей модели.

## 9. Если нужен настоящий мастер-шаблон

PptxGenJS не умеет использовать мастер-слайды из готового `.potx/.pptx`. Если заказчик потребует, чтобы файлы строились именно на официальном шаблоне:

1. Сделайте на сервере `POST /api/export` — принимает `Presentation` (тот же JSON, что возвращает `/api/generate`, после правок пользователя), собирает PPTX через `python-pptx` поверх шаблона и отдаёт файл.
2. Во фронтенде замените тело `downloadPptx` в `src/export/pptx-export.ts` на запрос к этому эндпоинту. Остальной интерфейс не меняется.
