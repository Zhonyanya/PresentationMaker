# PresentationMaker
проект по созданию презентаций в корпоративном стиле по написанному докладу при помощи модели искусственного интеллекта

## Презентатор — ИИ-ассистент для презентаций в корпоративном стиле

Фронтенд прототипа: сотрудник вставляет текст доклада или план выступления, получает структуру слайдов, редактирует её и скачивает **редактируемый PPTX**.

Сейчас приложение работает **полностью автономно** в демонстрационном режиме: структура строится в браузере простыми эвристиками. Языковую модель подключает бэкенд по контракту из [BACKEND_INTEGRATION.md](./BACKEND_INTEGRATION.md) — компоненты интерфейса при этом не меняются.

---

## Быстрый старт

Нужен Node.js 20 или новее (разработка и проверка велись на Node 25).

```bash
npm install        # 1. зависимости
npm run dev        # 2. запуск → http://localhost:5173
npm run build      # 3. production-сборка → папка dist/
npm run preview    #    посмотреть собранную версию
npm test           #    тесты (Vitest)
npm run typecheck  #    проверка типов
```

`dist/` — обычная статика: её можно отдать любым веб-сервером (nginx, S3, тот же сервер, что и бэкенд).

## Пользовательский сценарий

1. **Создание.** Название (необязательно), текст доклада или плана, примерное число слайдов. Текст можно вставить, загрузить из `.txt`/`.docx` или перетащить файл в поле. Есть три демо-примера.
2. **Генерация.** Экран с этапами. В демо-режиме этапы имитируются и помечены как «Демо». С настоящим API показывается честное неопределённое ожидание с таймером — без выдуманных процентов. Ошибки — с понятным текстом и кнопкой «Повторить».
3. **Редактор.** Слева миниатюры (выбор, перетаскивание, дублирование, удаление, меню «выше/ниже»), в центре превью 16:9, справа — макет, поля слайда, пункты списков и заметки докладчика. Изменения сразу видны в превью. Удаление и смена макета отменяются из уведомления. Презентация автоматически сохраняется в браузере и переживает перезагрузку.
4. **Экспорт.** «Скачать PPTX» → имя файла, заметки докладчика, проверка перегруженных слайдов → файл.

Горячие клавиши в редакторе: `↑/↓` — соседний слайд, `Alt+↑/↓` — переместить слайд, `Delete` — удалить слайд (когда фокус в списке слайдов), `Пробел` на миниатюре — взять и перенести стрелками. В списке пунктов: `Enter` — новый пункт, `Backspace` в пустом — удалить, `Alt+↑/↓` — порядок.

## Дизайн интерфейса

Редакционный стиль: тёплая бумажная основа, чернильный чёрный, один терракотовый акцент, линии в 1 px, без градиентов и «стекла».

- Шрифты: **Noto Serif Display** (заголовки) и **Inter Tight** (интерфейс), оба с кириллицей, подключаются локально через `@fontsource` — работают без доступа к Google Fonts.
- Токены цветов, радиусов и теней — `src/index.css`. Общие параметры анимаций — `src/components/app/motion.ts` (библиотека `motion`).
- Анимации учитывают системную настройку «Уменьшить движение» (`MotionConfig reducedMotion="user"`).
- Дизайн интерфейса и оформление слайдов — разные системы: слайды строго следуют `presentation-theme.ts`.

## Демонстрационный режим

Включён по умолчанию (`VITE_API_MODE=mock`).

- Генератор: `src/api/mock/mock-generator.ts` и `src/api/mock/text-analysis.ts`. Он выделяет заголовки (`#`, нумерация, короткие строки без точки, ЗАГЛАВНЫЕ), абзацы, списки и пары вида «Проблемы: … / Решения: …», раскладывает их по макетам и подгоняет число слайдов к запрошенному. Формулировки берутся из исходного текста, полный текст блока уходит в заметки докладчика. **Это не ИИ** — интерфейс честно помечает режим бейджем «Демо-режим».
- Ответ mock-генератора проходит ту же Zod-валидацию, что и ответ сервера.
- Проверить экран ошибки: откройте `http://localhost:5173/?mockFailEvery=1` — каждая генерация завершится ошибкой сервера.

## Подключение бэкенда

Коротко: поднимите `POST /api/generate` по контракту и создайте `.env`:

```bash
VITE_API_MODE=http
VITE_API_BASE_URL=https://api.example.ru   # пусто — тот же домен
VITE_API_TIMEOUT_MS=1500000                # 25 минут — лимит из ТЗ
VITE_DEV_PROXY_TARGET=http://localhost:8000 # только для npm run dev: прокси /api → бэкенд
```

Подробно — в **[BACKEND_INTEGRATION.md](./BACKEND_INTEGRATION.md)**: формат запроса и ответа, ошибки, CORS, промпт, чек-лист.

## Формат API (кратко)

```http
POST /api/generate
Content-Type: application/json

{ "text": "Текст доклада…", "title": "Итоги учебного года", "slideCount": 8 }
```

```json
{
  "title": "Итоги учебного года",
  "slides": [
    { "id": "slide-1", "layout": "title", "title": "Итоги учебного года", "subtitle": "Основные результаты", "caption": "Москва · 2026" },
    { "id": "slide-2", "layout": "bullets", "title": "Ключевые достижения", "bullets": ["…", "…"], "notes": "…" },
    { "id": "slide-3", "layout": "two-column", "title": "Основные направления", "leftTitle": "Было", "left": ["…"], "rightTitle": "Стало", "right": ["…"] },
    { "id": "slide-4", "layout": "closing", "title": "Спасибо за внимание" }
  ]
}
```

Макеты: `title`, `text`, `bullets`, `two-column`, `section`, `closing`. Полное описание полей — в BACKEND_INTEGRATION.md.

### Как устроено превью и экспорт

```
Slide (данные) ──► определение макета.buildScene() ──► SlideScene ──┬──► SlideRenderer (превью, px)
                                                                     └──► pptx-export (PptxGenJS, дюймы)
```

Сцена — список прямоугольников, текстов и изображений с координатами в дюймах и уже подобранным размером шрифта. Превью и PPTX рисуют **одну и ту же сцену**, поэтому совпадают. В PPTX каждый элемент — настоящий объект PowerPoint (текстовое поле, фигура), а не картинка.

## Корпоративная тема

Всё оформление слайдов — в одном файле **`src/theme/presentation-theme.ts`**. Сейчас там **временная нейтральная тема**: цвета и шрифты не являются официальными, логотипа нет. Интерфейс показывает бейдж «Временная тема», пока `isOfficial: false`.

Когда появится брендбук:

1. Замените `colors` (HEX), `fonts.heading` / `fonts.body` (имя шрифта, как оно называется в PowerPoint), при необходимости размеры в `typography` и поля в `spacing`.
2. Логотип: положите файл в `public/`, например `public/logo.png`, и укажите
   ```ts
   logo: { src: '/logo.png', width: 1.4, height: 0.6, onDarkSlides: true, srcOnDark: '/logo-white.png' }
   ```
   Размеры — в дюймах; изображение вписывается с сохранением пропорций.
3. Текст в колонтитуле — `footer.text`, номер слайда — `footer.showSlideNumber`.
4. Поставьте `isOfficial: true` и `name`.
5. Если сменился шрифт — перепроверьте коэффициенты ширины символа в `src/layouts/text-fit.ts` (там описано, как их замерить), иначе подбор размера будет неточным.
6. Схематичные миниатюры макетов в `src/features/editor/LayoutPicker.tsx` нарисованы цветами временной темы — обновите их под новую гамму.

Расположение элементов на слайдах (типовые макеты) задаётся в `src/layouts/definitions/*.ts`.

> **Шрифты.** PPTX хранит только имя шрифта. Если у сотрудника он не установлен, PowerPoint подставит замену. Для корпоративного шрифта его нужно установить на рабочие места.

## Как добавить новый макет

Пример: макет «Цитата».

1. **Схема** — `src/domain/presentation.ts`:
   ```ts
   export const quoteSlideSchema = z.object({ ...slideBase, layout: z.literal('quote'), quote: text(600), author: optionalText(200) })
   ```
   Добавьте её в `slideSchema` и в `generatedSlideSchema` (с `.extend(optionalId)`).
2. **Определение** — `src/layouts/definitions/quote.ts` по образцу `section.ts`: `label`, `description`, `icon`, `fields` (поля правой панели), `fromContent`/`toContent` (перенос текста при смене макета), `buildScene` (геометрия в дюймах; используйте `fittedText` из `chrome.ts`).
3. **Реестр** — строка в `src/layouts/registry.ts`.
4. Готово: макет появится в выборе макета и меню «Добавить», в превью и в PPTX. Тест `у каждого макета из схемы есть определение в реестре` подскажет, если что-то забыто. По желанию — схематичная миниатюра в `LayoutPicker.tsx` (иначе показывается иконка).
5. Сообщите бэкенду о новом значении `layout` (BACKEND_INTEGRATION.md).

## Ограничения прототипа

- **Мастер-слайды.** PptxGenJS создаёт слайды кодом и **не может использовать мастер-слайды и макеты из готового .pptx/.potx-шаблона**. Оформление воспроизводится по значениям из темы: цвета, шрифты и расположение совпадут, но в PowerPoint у слайдов не будет «корпоративного» мастера и макетов из меню «Макет». Если заказчик потребует строгого соответствия мастер-шаблону, сборку PPTX нужно перенести на бэкенд (например, `python-pptx` поверх официального шаблона). Контракт данных при этом остаётся тем же — фронтенд отправит презентацию на сервер вместо локальной сборки.
- **Подбор шрифта приблизительный.** Размер оценивается по средней ширине символа для Arial, а не измеряется PowerPoint. Если текста слишком много, шрифт уменьшается до аварийного минимума (9 pt), а редактор предупреждает и предлагает разделить слайд. В PPTX у текстовых полей включено «Сжимать текст при переполнении» — оно срабатывает, когда текст правят уже в PowerPoint.
- **Демо-генератор — не ИИ.** Он не пересказывает и не сокращает текст по смыслу, а раскладывает исходные формулировки.
- **Хранение — только в браузере** (`localStorage`): одна текущая презентация на браузер, без синхронизации между устройствами.
- **Изображения, диаграммы и таблицы** на слайдах не поддерживаются.
- **DOCX** читается в браузере (mammoth): сохраняются заголовки, абзацы и списки; таблицы и картинки игнорируются. Старый `.doc` не поддерживается.
- Нет авторизации и серверного хранения — сознательно, это MVP.
