# Контракт ML-модуля

Обязательные условия совместимости с существующим backend. Выбор модели, провайдера, алгоритмов, промптов и внутренней организации ML остаётся за разработчиком.

## Интерфейс

Импортируемый Python-модуль в окружении backend/worker; Python `>=3.13,<3.15`. Настройки: `PM_ML_ADAPTER=module`, `PM_ML_MODULE=presentation_ml` (либо другое импортируемое имя).

```python
PRESERVES_SLIDE_IDS = True

def generate(*, text, slideCount, job_id, deadline, title=None):
    ...

def revise(*, document, text, slideCount, instruction, target_slide_numbers,
           target_slide_ids, job_id, deadline):
    ...
```

Допустимы синхронные и `async def` функции. Аргументы передаются по имени, включая camelCase `slideCount`. Для командных правок обязательны `revise` и флаг `PRESERVES_SLIDE_IDS = True`.

| Аргумент | Значение |
|---|---|
| `text` | Исходный доклад после trim, 100–60 000 кодовых единиц UTF-16; при правке — сохранённый исходник |
| `title` | Только generate: необязательное название после trim, ≤200 UTF-16; если не задано, аргумент не передаётся |
| `slideCount` | Желаемое общее число слайдов, целое 3–20; при правке наследуется и может отличаться от фактического количества |
| `document` | Только revise: полный серверный снимок; входной объект не изменять |
| `instruction` | Только revise: команда после trim, 1–10 000 Unicode code points |
| `target_slide_numbers` | Только revise: уникальные номера слайдов с 1 в пределах снимка либо `None` |
| `target_slide_ids` | Только revise: соответствующие ID из снимка в порядке перечисления номеров либо `None` |
| `job_id` | Строковый UUID задания; доступен для корреляции и внешней идемпотентности |
| `deadline` | Абсолютный срок ISO 8601 UTC с часовым поясом, не длительность |

Без явного выбора оба списка целей равны `None`. Backend не извлекает цели из текста команды. Полная перегенерация вызывает `generate` без старого документа.

## Результат

Обе функции возвращают **полный документ** `{"title": string, "slides": [...]}` как `dict`, JSON-строку или JSON-байты UTF-8. Не patch, файл, поток, массив слайдов или обёртку `{"document": ...}`. Новые HTTP-маршруты, запись в БД и сборка PPTX не входят в ответственность ML.

Общие поля слайда: `layout`, `title: string ≤200`, `id` по правилам операции ниже; необязательное `notes: string ≤10 000`. Название документа `title` обязательно, ≤200. Общая схема допускает 1–60 слайдов.

| `layout` | Дополнительные поля |
|---|---|
| `title` | `subtitle?`: string ≤400; `caption?`: string ≤200 |
| `text` | Обязательное `body`: string ≤4000 |
| `bullets` | `bullets`: до 12 строк, каждая ≤1000; при отсутствии — `[]` |
| `two-column` | `leftTitle?`, `rightTitle?`: string ≤120; `left`, `right`: по ≤12 строк ≤1000, отсутствующие списки — `[]` |
| `section` | `subtitle?`: string ≤400 |
| `closing` | `subtitle?`: string ≤400 |

- Типы строгие. Необязательные поля опускаются, а не передаются как `null`. NUL (`\u0000`) в сохраняемых строках запрещён.
- Лимиты текстовых полей документа считаются в **кодовых единицах UTF-16**. Лимит `instruction` — исключение: Python считает Unicode code points.
- Неизвестные поля удаляются; неизвестный макет отклоняется. Поддерживается обычный текст, не HTML/Markdown-форматирование, изображения, таблицы или диаграммы. Оформление и PPTX задаёт frontend.
- Предел результата — `PM_MAX_ML_BYTES`, по умолчанию **8 000 000 байт**. Проверяется исходный JSON и сериализация объекта, включая лишние поля и повторную проверку после нормализации.

## Инварианты операций

### Генерация и полная перегенерация

- Первый макет — `title`, последний — `closing`: фактически минимум 2 слайда при общем максимуме 60.
- Отсутствующие и повторные ID заменяются backend на UUID; краевые пробелы ID удаляются. Пустой, пробельный или `null` ID отклоняется. Переданный ID не обязан быть UUID.
- `slideCount` — ориентир, а не проверка точного равенства. Сохранение ID старого документа при перегенерации не требуется.

### Командная правка

- Все ID, количество и порядок слайдов сохраняются точно. ID обязательны, уникальны, непусты и без краевых пробелов. Смысловая принадлежность содержимого слайду также сохраняется.
- При явных целях изменяются только выбранные слайды; остальные слайды целиком и общий `document.title` неизменны, **даже если выбраны все номера**.
- Без явных целей разрешено менять содержимое/макеты всех слайдов и общий title, но не структуру/ID. Смена макета допустима по его схеме; правило первого title/последнего closing проверяется backend только при генерации.
- Добавление, удаление и перестановка через `revise` не поддерживаются. Неподдерживаемая команда/операция — `NotImplementedError`, без подмены полной генерацией или фиктивного успеха.

## Ограничения выполнения и ошибки

- Каждый вызов — **новый Python-процесс**; на состояние в памяти предыдущего задания рассчитывать нельзя. Импорт модуля должен укладываться в readiness-бюджет **5 секунд** и не запускать платные операции. Readiness проверяет только импорт и callable `generate`, не работоспособность модели/правок.
- Общий бюджет — по умолчанию **1500 секунд от принятия задания**, включая очередь, инициализацию, ML, проверку и сохранение. Вызов должен завершиться до переданного `deadline` с запасом на публикацию; watchdog принудительно завершает группу процесса. Локальное завершение не гарантирует отмену операции у внешнего провайдера.
- Backend не повторяет начатый ML-вызов автоматически и не обещает exactly-once внешних платных операций. Внутренние повторы/многошаговые вызовы должны укладываться в согласованные стоимость и deadline. Сбой не подменяется fixture/mock; остановка ожидания в браузере не отменяет Job.
- Ошибка сообщается исключением, а не документом с полем `error`. `NotImplementedError` → `ML_CAPABILITY_UNAVAILABLE`; ошибка импорта модуля/его зависимости → `ML_UNAVAILABLE`; ошибки формата/инвариантов, `ValueError`/`TypeError`/`KeyError` → `INVALID_ML_RESPONSE`; прочие обычные исключения → `GENERATION_FAILED`. Текст исключений не является публичным сообщением.
- Результат возвращается значением функции. Вывод нативных библиотек/дочерних процессов в stdout не должен нарушать внутренний JSON-протокол. Доклады, команды, документы и ключи не должны попадать в логи; секреты модели остаются на сервере.

## Требования к содержимому

Генерация должна сохранять факты исходного доклада, учитывать название и желаемое число слайдов; правка — выполнять команду в разрешённой области без выдуманных фактов. Контент должен быть читаемым: максимальная допустимая длина поля не гарантирует его вместимость на слайде. Эти требования не проверяются одной JSON-валидацией.
