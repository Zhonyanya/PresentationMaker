# Работа с ML

- Контракт интеграции: `ML_CONTRACT.md`. ML возвращает документ; очередь, БД и PPTX принадлежат другим слоям.
- Реализация: `backend/presentation_ml`; настройка и результаты проверок: `docs/GIGACHAT_ML.md`.
- Текущая модель — `GigaChat-3-Ultra`. Другие модели и провайдеры не сравнивать и не подключать без нового поручения пользователя.
- Промпты: `prompts.py`, `prompt_templates/`; транспорт GigaChat: `providers/gigachat.py`.
- `generate` и `revise` не должны менять внешний интерфейс, ID или область выбранной правки.
- Сначала используйте сохранённые результаты и локальные тесты. Живые проверки запускайте только для конкретного изменённого поведения, последовательно, без скрытых повторов и LLM-судьи.
- Целевые проверки из `backend`: `uv run --locked pytest -q tests/test_presentation_ml.py tests/test_ml_providers.py tests/test_ml_acceptance.py`; запускайте их при соответствующих изменениях, а не автоматически при чтении проекта.
- `tools/ml_acceptance.py` сохраняет результат или неуспешную попытку; не обходите защиту от повторного платного вызова без явного решения и диагностики.
- Не выводите ключи, access token, `.env`, доклады или команды в журналы. TLS должен оставаться включённым.
- Реальные материалы и план `docs/NEXT_SESSION_ML.md` остаются локальными; не добавляйте их, `.idea/` или секреты в коммиты.
- Рабочая ветка этой задачи — `ml`. Не переносите изменения в `main` без отдельного поручения.
- Синтетические smoke-проверки не заменяют приёмку на реальных докладах. Hugging Face и другие провайдеры отложены пользователем.
